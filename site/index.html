Strong coffee

A pod coffee machine, written first as it often is (unsafe, messy and wrong, with passing tests), then made safe, cleaned into domains, its errors found, and finished strong.

The slides The code The approach

Safe ⇒ Strong. The assumption, first: every line of code is safe. It commits no memory error, it ends, and it touches nothing it was not lent. Safe, not correct.

Given that, strong is proved: each domain is isolated, reasoned about alone, and its invariants are proved for every input.

The five branches

  1. 1-unsafe One file, the state in globals. The tests pass. How many errors can you find?
  2. 2-safe Sanitizers and seeded random commands find five memory errors. Safety first: until it is safe, nothing can be reasoned about.
  3. 3-domains Each rule in its own domain, its state private, its invariant written. No answer changes; each rule can now be read alone.
  4. 4-errors Each rule tried for every input. The compiler, the invariants and the claims find nine errors, and one input each shows it is the code, not the proof.
  5. 5-strong Each error fixed where it lives. Every domain proved, and what the four do together.

Run it

git clone https://github.com/wmacevoy/strong-coffee
cd strong-coffee
git switch 1-unsafe && make test

From 4-errors on, the domains are proved; the README says how to get Lean and the prover's Python.
